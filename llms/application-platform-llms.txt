# MainPath

> MainPath for fast product development with stable architecture and automated delivery.

MainPath sets up complete software projects. Repository, CI/CD, servers, domains, workspaces and app store releases. Operation and data processing happen inside the EU, and the code stays yours.

Each HTML page also has a Markdown copy at the same path with index.md (and as page.md via the server). Use those files instead of scraping the HTML.

- [Your own server (SSH)](https://www.mainpath.ai/en/docs/own-server/index.md): You connect an existing Linux server to MainPath over SSH, and MainPath then sets it up and uses it for deployments.

- [Create an SSH key and add it to your server](https://www.mainpath.ai/en/docs/create-ssh-key/index.md): You generate an SSH key pair in the terminal, place the public key on the server, and store the private key in MainPath.

- [Webspace (FTP/SFTP)](https://www.mainpath.ai/en/docs/webspace-ftp/index.md): Projects that consist of homepages only are uploaded by the pipeline to an existing webspace over FTP or SFTP, so no Docker server is needed.

- [Cloud servers with your account](https://www.mainpath.ai/en/docs/cloud-servers/index.md): MainPath creates and sets up servers in your own Hetzner or Hostinger account, so the servers belong to you and you pay the provider directly.

- [Create a server at Hetzner](https://www.mainpath.ai/en/docs/hetzner-tutorial/index.md): You generate an API token in the Hetzner Cloud Console, store it in MainPath, and let MainPath create a server in your Hetzner account with it.

- [Create a server at Hostinger](https://www.mainpath.ai/en/docs/hostinger-tutorial/index.md): You generate an API token in the Hostinger hPanel, store it in MainPath, and let MainPath create a VPS in your Hostinger account with it.

- [Managed server](https://www.mainpath.ai/en/docs/managed-server/index.md): MainPath provisions, sets up, and operates a managed server itself and bills it through your subscription, so you do not need an account with a cloud provider.

- [Domain](https://www.mainpath.ai/en/docs/domain/index.md): To make your project reachable under a name of its own, you enter a domain and set the DNS records MainPath shows you at your domain provider.

- [Buy a domain](https://www.mainpath.ai/en/docs/buy-domain/index.md): MainPath does not sell domains, so you buy one from a registrar and make sure above all that you can edit its DNS zone yourself.

- [Configure DNS](https://www.mainpath.ai/en/docs/domain-how-to/index.md): You copy the DNS records from MainPath's domain detail into your domain provider's DNS management and wait until a check mark appears in the Status column.

- [Set DNS with Cloudflare](https://www.mainpath.ai/en/docs/dns-cloudflare/index.md): If your domain is hosted at Cloudflare, you connect an API token once and MainPath writes the A and CNAME records into your zone itself.

- [Publish apps (iOS and Android)](https://www.mainpath.ai/en/docs/publish-apps/index.md): The pipeline builds and signs your app, distributes it to TestFlight and the Internal Track, and then waits for you to release it to the store.

- [Store accounts](https://www.mainpath.ai/en/docs/store-accounts/index.md): MainPath only uploads builds to Apple and Google when your organization has given it access to App Store Connect and the Google Play Console.

- [Apple developer account and App Store Connect](https://www.mainpath.ai/en/docs/app-store-developer-account/index.md): Before you can create an API key for MainPath, you need a membership in the Apple Developer Program and access to App Store Connect.

- [App Store credentials](https://www.mainpath.ai/en/docs/app-store-credentials/index.md): How to create an App Store Connect API key and store it in MainPath together with the team ID and team name.

- [App Store: Create a bundle identifier](https://www.mainpath.ai/en/docs/app-store-bundle-identifiers/index.md): For iOS and macOS, MainPath offers the bundle identifiers of your Apple team for selection; you create new identifiers in the Apple Developer portal.

- [Google Play developer account](https://www.mainpath.ai/en/docs/google-play-developer-account/index.md): For Android releases through Google Play you need a developer account in the Google Play Console before you can create a service account for MainPath.

- [Play Store credentials](https://www.mainpath.ai/en/docs/play-store-credentials/index.md): How to create a Google Cloud service account for the Google Play Android Developer API, grant it access in the Play Console, and store the JSON key in MainPath.

- [Play Store: Create an app and package name](https://www.mainpath.ai/en/docs/play-store-package-names/index.md): For Android, MainPath offers the apps of your Play Store account for selection; you create a new app with its package name in the Google Play Console.

- [Android: Import the upload key](https://www.mainpath.ai/en/docs/android-keystore-import/index.md): An app that is already on Google Play must keep being signed with its original upload key; you import that key into MainPath once.

- [Store metadata: title, description, and screenshots](https://www.mainpath.ai/en/docs/store-metadata/index.md): All store texts and images of your app live version-controlled in the app repository, and the pipeline uploads them every time it publishes.

- [App store review notes](https://www.mainpath.ai/en/docs/app-store-review/index.md): Apple and Google review every submission before the app appears in the store; a demo account for the reviewers and complete metadata prevent the most common rejections.

- [Publish desktop applications](https://www.mainpath.ai/en/docs/publish-desktop-apps/index.md): The pipeline builds installers for macOS, Windows, and Linux, signs them if you want, and uploads macOS apps to the Mac App Store when needed.

- [Azure Artifact Signing: setup](https://www.mainpath.ai/en/docs/azure-artifact-signing-setup/index.md): How to create an Artifact Signing account in Azure, get your organization verified, and set up the certificate profile and service principal for the pipeline.

- [Azure Artifact Signing: credentials](https://www.mainpath.ai/en/docs/azure-artifact-signing-credentials/index.md): MainPath signs Windows builds with your service principal and certificate profile from Azure, whose values you store once for the organization.

- [Microsoft Store: developer account](https://www.mainpath.ai/en/docs/microsoft-store-developer-account/index.md): For the Microsoft Store you need a Partner Center account with an associated Entra tenant and a created app before you can generate credentials for MainPath.

- [Microsoft Store: credentials](https://www.mainpath.ai/en/docs/microsoft-store-credentials/index.md): MainPath submits Windows apps through an Entra app registration with the Partner Center Manager role, whose values you store together with the Seller ID.

- [Publish browser apps](https://www.mainpath.ai/en/docs/publish-web-apps/index.md): A browser app built with Flutter Web, React Native Web, or Next.js runs as a Docker container on your server, gets its dev address automatically, and uses your own domain in production.

- [Publish websites](https://www.mainpath.ai/en/docs/publish-websites/index.md): Hugo and Astro sites consist of static files that the pipeline builds and delivers either to your Docker server or to an existing web space.

- [Publish the backend](https://www.mainpath.ai/en/docs/publish-backend/index.md): Your NestJS, FastAPI, or Laravel backend runs as a Docker container on your server, together with the MySQL database, the uploads, and the helper services that belong to it.

- [Backups](https://www.mainpath.ai/en/docs/backups/index.md): Easy Backup backs up the MySQL database and the uploads of your backend on a schedule or on demand and restores individual backups.

- [Operations](https://www.mainpath.ai/en/docs/operations/index.md): After the first deployment, the work shifts to spotting errors early, tracing releases, and going back to the last working state when needed.

- [Libraries](https://www.mainpath.ai/en/docs/libraries/index.md): A project can contain package repositories whose pipeline publishes your own packages and Docker images to the private GitLab registries of your organization.

- [Whitelabel apps](https://www.mainpath.ai/en/docs/whitelabel-apps/index.md): In whitelabel mode you run several brand variants from one app codebase, each with its own name, logo, domains, and store listings.

- [Architecture](https://www.mainpath.ai/en/docs/architecture/index.md): GitLab pipelines build Docker images, a GitOps repository records which version runs where, and Ansible brings that state to servers that MainPath has set up with Traefik, a firewall, and HTTPS.
